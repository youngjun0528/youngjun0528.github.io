# 01.01 LLMOps

## 프롬프트 엔지니어링 ( Prompt Engineering )

- LLM 을 효과적으로 사용하기 위해 입력 프롬프트를 설계하고 최적화하는 과정

1. 정확한 응답 유도
2. 모델의 능력 극대화
3. 사용자 겸헝 개선
4. 비용 절감 및 효율성 개선

## LLMOps Goals

1. 자동화
2. 표준화된 워크 플로
3. 협업 강화
4. 비용 절감 및 자원 최적화
5. 데이터 관리 및 보안
6. 버전 관리

> # 파인 튜닝
> - 이미 사전 학습된 언어 모델에 도메인 별 데이터나 특정 태스크 데이터를
    추가로 학습시켜 특정 목적에 최적화된 성능을 발휘하도록 미세 조정하는 과정

### MLOps 와 LLMOps 의 차이점

두가지 모두 AI 모델의 운영과 관리를 체계와 하는 프로세스

#### MLOps

- 예측 모델, 분류 모델, 회귀 모델 등 비교적 단순한 머신러닝 모델
- 구조화된 데이터를 기반

특징
: - 컴퓨팅 자원 요구량이 적음
: - 신속한 훈련과 배포
: - 모델 크기와 유지 관리의 용이성

데이터 관리
: - 데이터 전처리
: - 피처 엔지니어링 : 모델 성능을 향상 시키기 위해 원본 데이터를 변환하거나 새로운 피쳐를 생성하는 과정
: - 데이터 크기와 정형화된 처리 과정

커스터마이징과 최적화
: - 모델 설계의 유연성
: - 하이퍼파라미터 최적화

모니터링
: - 성능 지표 기반 모니터링
: - 데이터 드리프트 감지 : 시간이 지남에 따라 입력데이터의 동톄적 특성이 변하는 현상으로 모델의 성능 저하 발생

#### LLMOps

- GPT, Claude, llama 와 같은 LLM 을 대상
- 비정형 데이터를 처리

특징
: - 대규모 검퓨팅 자원 필요
: - 긴 훈련 시간 및 높은 비용
: - 상업용 클로즈드 모델 사용
: - 파인 튜닝의 중요성

데이터 관리
: - 텍스트와 코드 데이터 (자연어 처리)
: - 데이터 품질 관리의 중요성
: - 복잡한 전처리 작업

커스터마이제이션과 최적화
: - 프롬프트 엔지니어링 : 모델에게 특정한 방식으로 응답하도록 지시하는 입력 명령어 설계
: - 파인 튜닝 : 특정 도메인 데이터셋을 추가로 학습하며, 이를 통해 도메인에 특화된 언어패턴과 지식을 습득

모니터링
: - 출력 품질 모니터링
: - RLHF 인간 피드백을 통한 강화 학습
: - 보안 및 프라이버시 모니터링

> # 환각 현상
> LLM 이 실제 존재하지 않는 정보나 잘못된 사실을 생성하는 현상, 이는 모델이 학습 데이터에 없는 질문에 대해 유추할 때 발생

> # 프롬프트 인젝션
> LLM에서 프롬프트에 의도적으로 악성 또는 예상치 못한 내용을 주입해서 모델의 응답을 조작

> # 모델 종류
> ## 상업용 클로즈드 모델
> - 일정 비용을 지불하고 사용하며, 모델의 구조, 데이터 훈련 방식 등 세부사항은 비공개
> - ex) GPT-4, gemini
>
> ## 사전 훈련된 오픈소스 모델
> - 대규모 데이터셋을 바탕으로 훈련된 고개 모델
> - 누구나 사용이 가능하고, 추가학습을 통해 특화 용도로 사용 가능
> - ex) llama, gemma

## 모델 파라미터

| 파라미터(OpenAI)      | 파라미터(Ollama)   | 설명                                 | 예시                                                                   |
|-------------------|----------------|------------------------------------|----------------------------------------------------------------------|
| temperature       | temperature    | 출력의 무작위성 제어                        | 0에 가까울 수록 일관되고 예측 가능한 결과<br/>1에 가까울 수록 창의적인 다양한 결과                   |
| max_tokens        | num_predict    | 생성할 텍스트의 최대 토큰 수 설정                | 맥락에 따라 적절하게 조정 필요, 짧은 답변이 필요할 때에는 값을 낮추고, 긴 답변이 필요할 때는 값을 높임         |
| top_p             | top_p          | 상위 확률에 해당하는 토큰들만 선택해서 다양성을 조절      | 높은 값은 다양성을 줄이고 가장 가능성이 높은 선택지를 고르고,<br/>낮은 값은 더 창의적이고 예측 불가능한 답변을 생성 |
| frequency_penalty | repeat_penalty | 모델이 이미 생성한 단어를 반복하는 것을 방지하기 위한 페널티 | 값이 높을수록 반복되는 단어를 덜 생성함                                               |
| presence_penalty  | - (미지원)        | 새로운 주제를 도입하는 것을 장려하거나 억제하는 페널티     | 창의적인 아이디어나 새로운 주제가 필요할 때 값을 높이고, 특정 주제에 집중하고 싶을 때는 값을 낮춤             |

### 예시

```python
import requests

resp = requests.post(
    "http://localhost:11434/api/chat",
    headers={"Content-Type": "application/json"},
    json={
        "model": "gemma3:1b-it-qat",
        "messages": [
            {
                "role": "system",
                "content": "주어진 질문에 대해 간단하고 명확한 답변을 제공해주세요."
            },
            {
                "role": "user",
                "content": "현재 제공 가능한 최신 Python 버전은 어떤 거야?"
            }
        ],
        "options": {
            "temperature": 1.00,
            "num_predict": 100,
        },
        "stream": False
    }
)

if resp.status_code == 200:
    print(resp.json())
```

> # 주요 파라미터
> - model : 사용할 모델 지정
> - messages : 대화의 흐름을 정의하는 메세지 목록
> > - 각 메세지는 rule(system, suer, assistant) 와 content 로 구성
> - options : 모델 파라미터
> > - temperature : 응답의 다양성을 조절 ( Default : 0.08, Range : 0.0 ~ 1.0 )
> > - num_predict : 생성할 응답의 최대 토큰 수 ( Default : 128 )
> - streams : 스트리밍 모드 여부 ( Default : true)

## 프롬프트의 구성 요소

### Prompt Role (프롬프트 역할)

1. 시스템(System)
    - 모델의 행동과 응답 스타일을 정의하는 작업 지시 내용이 포함
2. 사용자 (User)
    - 사용자가 모델에 전달하는 질문이나 요청, 또는 명령
3. 어시스턴트 (Assistant)
    - 모델이 생성한 응답

### Prompt Template (프롬프트 템플릿)

다양한 입력 데이터를 처리하면서 일관되고 효과적으로 모델을 활용하기 위해 프롬프트의 구조를 체계적으로 설계하는 방법

- 반복 작업의 효율성을 높이고, 모델에 주어진 작업을 명확히 이해
